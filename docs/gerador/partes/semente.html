35.1As duas salvaguardas

{{cod:seed-salvaguarda|ts|prisma/seed.ts — a trava}}
  1. Se já houver qualquer animal cadastrado, a demonstração não roda. Dado de verdade nunca é sobrescrito. Essa checagem acontece a cada boot do container, porque o entrypoint chama a semente sempre.
  2. SEMEAR_DEMONSTRACAO=false desliga de vez. É o interruptor a virar no dia em que o primeiro animal real for cadastrado.

Os catálogos base — configuração da ONG e os três acessos de equipe — são semeados sempre, de forma idempotente por upsert. Eles não são demonstração: são o mínimo para alguém conseguir entrar no sistema.

35.2Por que os dados são realistas

Dados fictícios servem para testar a interface, e interface só é testada por dados que se parecem com os reais. A semente foi escrita com isso em mente:

CaracterísticaPor quê
Gerador determinísticoUm PRNG linear com semente fixa (20260922). O mesmo abrigo é gerado toda vez; sem isso, cada deploy mostraria números diferentes e ninguém conseguiria conferir se algo quebrou.
~9% de inadimplênciaUm sistema com 100% de pagamento não exercita a tela de cobrança nem o alerta do painel.
~12% de cancelamentoDá ao gráfico de retenção o que mostrar. Um gráfico de novos × cancelados sem cancelamento não ensina a ler o gráfico.
Mês corrente parcialmente pago62% pago, o resto pendente ou atrasado conforme o vencimento — que é exatamente o estado real de um dia 22.
Poucas cirurgias caras7% dos animais têm um procedimento acima de R$ 1.200. É o que justifica a existência de campanha e o que faz o relatório de concentração de custo ter sentido.
Histórias de resgate escritasDez textos reais de tom, não lorem ipsum. É esse texto que faz alguém parar o scroll, e testar a vitrine com texto falso não testa nada.
Coerência temporalNenhum apadrinhamento começa antes do resgate do animal ou do cadastro do padrinho; nenhum cancelamento tem data futura; nenhuma saída de estoque deixa saldo negativo.
Sem fotos, e de propósito

A semente não cria arquivos de imagem. Os animais aparecem com o retrato gerado — gradiente determinístico com a inicial do nome —, o que também serve para validar esse caminho da interface. Os comprovantes fictícios existem como metadado, mas o arquivo não: abrir um deles devolve 404, e é melhor assim — comprovante de mentira não deve abrir como se fosse documento de verdade.

A senha não está no código

A senha dos três vem de SENHA_DEMO, no .env. Deixando a variável em branco, a semente sorteia uma e a imprime uma única vez no log do boot — quem subiu o container a lê com docker compose logs app, e mais ninguém.

O motivo é direto: o repositório é público, e senha de administrador versionada é senha de administrador publicada. Vale a mesma regra para o .env.example, que vai para o Git.

Antes de expor o sistema

Troque as senhas dos três acessos, pela tela de configurações ou por scripts/criar-usuario.ts. Uma senha sorteada no boot é melhor do que uma senha publicada, mas continua sendo uma senha de demonstração.
